# Spectra Workbench 项目工程与工作流使用指南

本文档详细说明 Spectra Workbench 的工程持久化文件格式规范、DAG 工作流定义编排、批处理模板配置以及隔离脚本会话的使用示例。

---

## 1. 工程项目文件规范 (`.spectra.json`)

Spectra Workbench 采用结构化、严谨的 JSON 格式记录用户工作区状态。所有关键数据（包括数据源映射、图层视口顺序、渲染样式、空间参考、交互式 ROI 与 Dock 窗口布局）均通过原子事务写入磁盘。

### 核心设计原则
1. **相对路径优先与锚点机制 (`path_anchor`)**：
   - 当工程保存于某目录时，系统记录 `path_anchor: "project_dir"`；
   - 位于工程同级或子目录的数据集以相对路径（如 `"sources/dem.tif"`）保存，确保整个工程文件夹可整体打包迁移至任意磁盘或机器无损重开；
   - 跨磁盘或绝对路径源保留权威 URI，VSI 虚拟文件系统保留规范化 POSIX 前缀（如 `/vsizip/...`）。
2. **缺失源安全隔离与防止误劫持**：
   - 打开工程时若底层数据源被移除，工程依然正常打开，并将该数据源标记在 `missing_sources` 隔离区；
   - 严禁盲目自动匹配同名文件，防止路径歧义导致的数据劫持；
   - 用户可在 UI 中主动重新关联物理文件或显式移除图层；保存时保全权威几何与图层样式配置。
3. **崩溃恢复与原子保存 (Atomic Save)**：
   - 采用同卷临时文件暂存（`target.tmp`）并在内容完整刷盘后再执行 `os.replace`；
   - 进程被强制终止时，原有 `.spectra.json` 字节 100% 完好无损，且不残留临时污点文件。

## 2. DAG 工作流 (Workflow DAG) 规范与示例

Spectra Workbench 提供强类型、跨引擎的 DAG 工作流引擎 (`processing/workflow.py`)。它支持将不同引擎（如 GDAL、Rasterio、NumPy/SciPy）的能力无缝串联，并在拓扑执行中实施自动指纹校验与缓存复用。

### 核心机制
- **端口类型强约束**：显式声明输入输出端口的 `kind: raster` 或 `kind: vector`。如果消费者节点连接了类型不匹配的生产者端口，将在提交校验阶段直接拦截，杜绝运行时异常；
- **环检测 (Cycle Detection)**：提交前执行 Kahn 算法拓扑排序，若存在循环依赖精准报错并列出环成员；
- **跨引擎结果物化与传递**：例如节点 A 由 GDAL 引擎执行山体阴影计算，产物生成后自动作为物理成果提交，节点 B 由 Rasterio 引擎直接读取该产物进行分块格式转换；
- **按指纹智能缓存 (`fingerprint caching`)**：根据节点参数 JSON、上游依赖产物的哈希及修改时间生成快照；若上游未变更，重跑工作流时自动命中 `cached`，计算时间降为 0。

### 工作流定义示例 (`workflow_terrain_pipeline.json`)

```json
{
  "schema_version": "1.0",
```

## 3. 批处理 (Batch Processing) 模板规范与示例

批处理模块 (`processing/batch.py`) 用于对大批量同构数据集执行统一算子处理。

### 模板展开与错误控制
- **参数占位符自动展开**：模板参数支持引用条目属性，如 `"{item[filename]}"`、`"{item[output_dir]}/{item[basename]}_hillshade.tif"`；
- **容错策略 (`continue_on_error`)**：
  - `continue_on_error: true`：单张影像异常时记录失败原因并继续执行剩余作业，最终生成包含 succeeded、failed、cancelled 终态与耗时的汇总审计报告；
  - `continue_on_error: false`：首个作业报错时立即停止，后续任务明确标记为 `pending(skipped)`，绝不冒充成功；
- **批处理清单 (`batch_manifest.json`)**：执行完成后自动落盘，完整记录执行时间戳、参数指纹与产物 SHA256。

### 批处理模板示例 (`batch_ndvi.json`)

```json
{
  "batch_name": "多时相植被指数批量计算",
  "capability_id": "gdal:sindex",
  "engine_provider": "science",
  "template": {
    "params": {
      "index": "NDVI",
      "redBand": 3,
      "nirBand": 4,
      "usePhysical": true,
      "format": "GTiff"
    },
    "overwrite": true
  },
  "items": [
    {
      "item_id": "scene_2026_03",
      "input": "data/time_series/scene_20260315.tif",
      "output": "outputs/ndvi/ndvi_20260315.tif"
    },
    {
      "item_id": "scene_2026_06",
      "input": "data/time_series/scene_20260620.tif",
      "output": "outputs/ndvi/ndvi_20260620.tif"
    },
    {
      "item_id": "scene_2026_09",
      "input": "data/time_series/scene_20260910.tif",
      "output": "outputs/ndvi/ndvi_20260910.tif"
    }
  ],
  "continue_on_error": true
}
```

## 4. 隔离脚本会话 (Isolated Scripting Session) 使用示例

为了保证主界面 UI 的高响应度与绝对稳定性，Spectra Workbench 提供隔离脚本会话机制 (`scripting/session.py`)。用户脚本直接在独立引擎解释器（GDAL 或 Rasterio 运行时）中执行原生 Python API，UI 进程不导入任何第三方 C 扩展。

### 交互执行示例 (Python API)

```python
from pathlib import Path
from spectra_workbench.scripting.session import ScriptSession

# 1. 建立针对 GDAL 独立引擎的隔离脚本会话
session = ScriptSession(
    engine="gdal",
    session_dir=Path("work/script_sessions/session_01")
)

# 2. 准备执行用户脚本（原生导入 osgeo 并执行栅格计算）
user_script = """
import os
from osgeo import gdal

print("正在独立 GDAL 引擎中执行自定义运算...")
driver = gdal.GetDriverByName("GTiff")
ds = driver.Create("work/script_sessions/session_01/output.tif", 256, 256, 1, gdal.GDT_Byte)
band = ds.GetRasterBand(1)
band.Fill(128)
ds.FlushCache()
ds = None
print("运算完成，产物已落盘！")
"""

# 3. 运行脚本并捕获输出
result = session.run_code(user_script)

print("执行状态:", result.success)
print("标准输出:\n", result.stdout)

# 4. 显式登记生成成果到工程上下文
session.register_artifact(Path("work/script_sessions/session_01/output.tif"))

# 5. 关闭会话，彻底回收子进程
session.stop()
```
