# Spectra Workbench 插件协议与自定义引擎扩展指南

Spectra Workbench 采用严格的**进程级物理隔离架构**。主图形界面 (GUI) 与底层地理信息/科学计算引擎（GDAL、Rasterio、SciPy）运行在互相隔离的独立操作系统进程中。本文档面向核心开发者与第三方插件开发者，详细说明进程隔离原则、JSONL 通信协议、能力契约 Schema 以及如何开发与集成自定义插件引擎。

---

## 1. 架构设计与进程边界原则 (Process Isolation)

### 为什么必须物理隔离？
1. **杜绝原生底层崩溃蔓延**：C/C++ 编写的底层 GIS 库（如 GDAL、PROJ、GEOS）在面对畸形栅格、悬空指针或损坏投影定义时，可能触发内存访问越界（Segmentation Fault / Windows 0xC0000005）。如果直接在 GUI 进程中调用，将导致整个桌面程序瞬间闪退且无法捕获异常；
2. **规避 DLL 地狱与动态符号冲突**：不同遥感库（如 Rasterio 内嵌的静态 GDAL 与 QGIS 系统 GDAL）对底层依赖库版本要求互斥，在同一进程内强行加载会引发未定义符号混淆；
3. **消除 UI 界面卡死**：长时间的大影像格式转换、空间重投影或迭代分析在独立子进程中串行或异步执行，主界面维持 60 FPS 丝滑响应。

### 架构红线
- **GUI 主进程红线**：主进程代码（`src/spectra_workbench/ui/`、`rendering/`、`project/`）**严禁**直接执行 `import osgeo`、`import rasterio` 或 `import scipy`；
- **Worker 职责单一**：Worker 进程仅负责执行特定能力计算，通过标准输入输出（stdin/stdout）与主进程进行 JSONL 通信，不创建任何 UI 控件。

---

## 2. 进程间通信协议 (JSONL Protocol)

主进程 (`WorkerClient`) 与 Worker 进程 (`WorkerProcess`) 之间通过单行换行分隔的 JSON 文本流通信。

### 协议消息格式

每条消息均为一个完整的 JSON 对象，包含 `schema_version`、`message_type`、`correlation_id`、`timestamp` 与 `payload`。

#### A. 握手与就绪通知 (`handshake`)
Worker 进程启动后，首先自检环境并将运行时元数据上报给主进程：

```json
{
  "schema_version": "1.0",
  "message_type": "handshake",
  "correlation_id": "init_001",
  "timestamp": "2026-11-10T08:00:00Z",
  "payload": {
    "engine": "gdal",
    "engine_version": "3.13.3",
    "python_version": "3.12.8",
    "pid": 14256,
    "capabilities": [
      "gdal:translate",
      "gdal:warp",
      "gdal:dem",
      "ogr:vectortranslate"
    ]
  }
}
```

#### B. 任务分发 (`task_submit`)
主进程向 Worker 提交带有完整校验参数的任务规约 (`TaskSpec`)：

```json
{
  "schema_version": "1.0",
  "message_type": "task_submit",
  "correlation_id": "req_8829",
  "timestamp": "2026-11-10T08:00:01Z",
  "payload": {
    "task_id": "task_hillshade_01",
    "capability_id": "gdal:dem",
    "inputs": {
      "input": "C:/data/elevation.tif"
    },
    "params": {
      "mode": "hillshade",
      "zFactor": 1.0,
      "azimuth": 315.0,
      "altitude": 45.0,
      "format": "GTiff"
    },
    "output_plan": {
      "staging_dir": "C:/temp/staging/task_hillshade_01",
      "target_file": "C:/output/hillshade.tif",
      "overwrite": true
    }
  }
}
```

#### C. 进度汇报与心跳 (`task_progress`)
Worker 在长计算过程中流式汇报进度与心跳：

```json
{
  "schema_version": "1.0",
  "message_type": "task_progress",
  "correlation_id": "req_8829",
  "timestamp": "2026-11-10T08:00:03Z",
  "payload": {
    "task_id": "task_hillshade_01",
    "fraction": 0.65,
    "stage": "正在计算光照表面阴影像元..."
  }
}
```

#### D. 成果确认 (`task_result`)
计算完成并生成产物后，Worker 上报实际提交的产物清单与执行元数据：

```json
{
  "schema_version": "1.0",
  "message_type": "task_result",
  "correlation_id": "req_8829",
  "timestamp": "2026-11-10T08:00:05Z",
  "payload": {
    "task_id": "task_hillshade_01",
    "status": "succeeded",
    "duration_seconds": 4.12,
    "committed_files": [
      "C:/output/hillshade.tif"
    ],
    "sidecars": {},
    "engine_runtime": {
      "engine": "gdal",
      "version": "3.13.3"
    }
  }
}
```

## 3. 能力契约与注册表体系 (Capability Contracts)

所有能力必须通过符合 `contracts/capability.schema.json` 规范的元数据描述。这使得前端 GUI 能在完全不知道底层实现细节的前提下，自动化渲染参数表单并执行预校验。

### 能力定义核心结构

```json
{
  "capability_id": "ext:gaussian_blur",
  "name": "高斯平滑滤波算子",
  "version": "1.0.0",
  "engine_provider": "science",
  "kind": "algorithm",
  "availability": "callable",
  "description": "基于 SciPy ndimage 高斯核对栅格波段进行空间连续平滑去噪",
  "parameter_schema": {
    "type": "object",
    "required": ["input", "sigma"],
    "properties": {
      "input": {
        "type": "string",
        "description": "输入栅格文件路径",
        "ui_widget": "file_open_raster"
      },
      "sigma": {
        "type": "number",
        "default": 1.5,
        "minimum": 0.1,
        "maximum": 50.0,
        "description": "高斯核标准差"
      },
      "output": {
        "type": "string",
        "description": "输出栅格文件路径",
        "ui_widget": "file_save_raster"
      }
    }
  }
}
```

## 4. 开发与接入自定义插件实战

要在 Spectra Workbench 中新增一项算法扩展，只需以下三个标准化步骤：

### 步骤一：创建能力契约定义
在 `contracts/overlays/` 或插件包内新增 `ext_gaussian_blur.json`（如上述第 3 节契约定义）。注册表扫描器启动时会自动加载该定义。

### 步骤二：实现主进程端适配器 (`ProviderAdapter`)
在 `src/spectra_workbench/providers/` 或插件模块中继承 `ProviderAdapter`，实现参数预校验与暂存提交计划：

```python
from pathlib import Path
from typing import Any
from spectra_workbench.providers.base import ProviderAdapter, ExecutionPlan
from spectra_workbench.domain.models import TaskSpec, TaskValidationError

class GaussianBlurAdapter(ProviderAdapter):
    def validate_spec(self, spec: TaskSpec) -> None:
        """提交前校验参数合法性，不抛出异常即为通过"""
        sigma = spec.params.get("sigma", 1.5)
        if not (0.1 <= float(sigma) <= 50.0):
            raise TaskValidationError("sigma 必须在 [0.1, 50.0] 范围内")

    def build_execution_plan(self, spec: TaskSpec, staging_dir: Path) -> ExecutionPlan:
        """构造暂存目录与产物交付计划"""
        output_target = Path(spec.output_plan.target_file)
        staged_file = staging_dir / output_target.name
        
        return ExecutionPlan(
            task_id=spec.task_id,
            capability_id=spec.capability_id,
            staging_dir=staging_dir,
            staged_artifacts=[staged_file],
            final_targets=[output_target],
            overwrite=spec.output_plan.overwrite,
            worker_command={
                "action": "execute_gaussian_blur",
                "input": spec.inputs["input"],
                "output": str(staged_file),
                "sigma": spec.params.get("sigma", 1.5)
            }
        )
```

### 步骤三：在 Worker 进程中注册实际计算逻辑
在 Worker 进程执行入口（`src/spectra_workbench/workers/entrypoint.py`）中注册对应动作处理器。此时可以安全导入 NumPy、SciPy 等原生重型依赖：

```python
def handle_gaussian_blur(command: dict[str, Any]) -> dict[str, Any]:
    """在独立的 science 运行时进程中执行物理平滑运算"""
    import numpy as np
    from scipy.ndimage import gaussian_filter
    from osgeo import gdal

    src_ds = gdal.Open(command["input"], gdal.GA_ReadOnly)
    band = src_ds.GetRasterBand(1)
    data = band.ReadAsArray().astype(np.float32)

    # 执行高斯滤波
    filtered = gaussian_filter(data, sigma=float(command["sigma"]))

    # 写入暂存文件
    driver = gdal.GetDriverByName("GTiff")
    dst_ds = driver.Create(
        command["output"],
        src_ds.RasterXSize,
        src_ds.RasterYSize,
        1,
        gdal.GDT_Float32
    )
    dst_ds.SetGeoTransform(src_ds.GetGeoTransform())
    dst_ds.SetProjection(src_ds.GetProjection())
    dst_ds.GetRasterBand(1).WriteArray(filtered)
    dst_ds.FlushCache()
    dst_ds = None
    src_ds = None

    return {"status": "ok", "produced": [command["output"]]}
```

### 验证与生效
完成上述三步后，重启应用：
1. **工具箱自动呈现**：算法工具箱自动扫描并呈现「高斯平滑滤波算子」；
2. **表单自动生成**：点击算法后，界面自动根据 Schema 渲染文件选择器与 Sigma 浮动滑块；
3. **安全执行**：点击「运行」即由主进程通过 WorkerClient 安全派发至后台独立 Worker 进程运算，运算完成自动加载至图层面板。
